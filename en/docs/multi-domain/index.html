Multi-domain support

Status: implemented (shipped since v1.3.0) Last updated: 2026-10-28

1. Summary

urlet serves short links on one canonical host plus any number of extra domains. The canonical host keeps the full application (/, /app/*, /api/v1/*). Extra domains are redirect-only: they answer GET /{slug} and POST /{slug}/unlock, render the theme-aware short landing page at /, and send everything else back to the canonical host (or reject it).

Each domain owns its own slug namespace: (domain_id, slug) is unique. The same slug may exist on a.example.com and b.example.com and resolve to different targets.

Implementation defaults agreed for the open points:

  • Domains seeded through URLET_DOMAINS are inserted as active and verified: they are declared by the operator in deployment configuration.
  • The short landing page is theme-aware (all six themes) and shows the site name, one explanatory sentence, a link to the canonical host and the site tools (theme picker, language switcher). No login, registration or slug input.
  • The current default domain cannot be disabled or deleted until another active domain is made default.
  • domains.source distinguishes system, env and ui. The system/canonical domain can be neither disabled nor deleted; environment-managed domains can be disabled but not deleted from the UI.

4. Data model

domains

Added by migration 0003_multi_domain:

ColumnMeaning
statuspending, active or disabled
sourcesystem (canonical), env (URLET_DOMAINS) or ui
updated_atLast lifecycle change

hostname is stored lower-case without a trailing dot and with an optional non-default port. A NOCASE unique index backs case-insensitive lookups. The existing is_default partial unique index keeps exactly one default domain.

urls

  • domain_id INTEGER NOT NULL REFERENCES domains(id) ON DELETE RESTRICT
  • UNIQUE (domain_id, slug) with the existing COLLATE NOCASE on slug
  • legacy NULL values are back-filled to the default domain
  • soft-deleted rows keep their (domain_id, slug) reservation

Migration 0005_group_domains adds the per-group domain policy: user_groups.default_domain_id, restrict_domains and the group_domains allowlist decide each member's effective default and selectable domains.

5. Migration 0003_multi_domain

Before renaming, the migration normalises hostnames into a temporary mapping and merges rows that become identical (case, trailing dot, default port). The survivor is the default row when the group has one, otherwise the lowest id; urls.domain_id is remapped to it and duplicate rows are deleted. This handles a v2 installation that changed URLET_BASE_URL from example.com:443 to example.com and therefore already had both rows.

SQLite cannot drop the inline UNIQUE on urls.slug, so the table is rebuilt with the official 12-step procedure. Because clicks, url_tags and url_daily_stats reference urls with ON DELETE CASCADE, the rebuild runs on a dedicated connection with PRAGMA foreign_keys = OFF outside the transaction. The migration runner distinguishes transactional migrations from rebuild migrations and always restores PRAGMA foreign_keys = ON before the connection is closed. PRAGMA foreign_key_check must return no rows before commit.

Before upgrading: back up the SQLite file. The migration has no down migration; rollback is restoring the backup and the previous binary. Tests seed a v2 database with URLs, clicks, tags and daily stats, apply 0003, and assert row counts, foreign keys, back-filled domains, per-domain slug uniqueness and a working sqlite_sequence.

6. Host resolution

  • Read the Host header. An absent Host (HTTP/1.0 and tests) is treated as the canonical host. A present but undecodable/invalid Host is an unknown host.
  • Normalise: trim, lower-case, strip a trailing dot, strip :80/:443, keep other ports, reject schemes, paths and control characters.
  • The canonical host may be an IPv6 literal or a Docker-style underscore service name; those are matched through an opaque ASCII fallback because extra domains still have to be normal hostnames. A Unicode canonical host must be supplied as punycode; an unparseable Unicode URLET_BASE_URL fails startup instead of silently serving 404s.
  • X-Forwarded-Host is not trusted in this version. The reverse proxy must preserve the original Host (Caddy does by default).
  • A DomainRegistry snapshot in AppState maps hostnames and ids to domains and remembers the active host list and default id. It is loaded during bootstrap and reloaded after every admin mutation. Direct database edits are picked up on the next restart.
  • The domain gate runs after locale negotiation and before CSRF. It inserts a HostContext extension (canonical or active domain) for handlers.
  • Unknown, pending and disabled hosts never reach redirect handlers.

7. Creating and displaying links

  • CreateInput and POST /api/v1/urls accept an optional domain hostname. Omitted resolves through the domain policy to the caller's group default (the site-wide default when the group has none, or the group's choice is no longer active). The target must be active and allowed by the caller's policy; pending and disabled domains are rejected.
  • The public creation paths POST / and POST /api/v1/public/urls also accept domain; the form echoes the resolved hostname back in its redirect, and the API returns domain alongside short_url.
  • All slug checks, generated-slug retries and update checks are scoped to the selected domain. Conflicts are reported with the hostname.
  • PATCH /api/v1/urls/{id} accepts domain; moving a link re-checks the slug on the target domain and returns 409 on a conflict.
  • UrlDto gains domain; short_url is {scheme}://{hostname}/{slug} using the instance scheme.
  • HTML create and edit forms show a domain select populated from the domains the caller's policy allows; the dashboard and detail pages open short_url rather than a relative path.
  • GET /api/v1/domains returns the active domains the caller's group domain policy allows, with is_default marking the group's effective default rather than the site-wide one.
  • GET /api/v1/public/urls/{slug}?domain=<hostname> resolves the default domain when the parameter is absent, preserving existing callers. The response gains domain.

8. Administration

  • New /app/admin/domains page and /api/v1/admin/domains endpoints.
  • Actions: add (pending), activate, disable, set default, delete.
  • Rules:
    • canonical (source = system) is always active and cannot be disabled or deleted. If URLET_BASE_URL changes, bootstrap creates the new canonical row, transfers the default when the previous system row held it, and demotes the previous system row to ui; its links keep resolving until an administrator disables it;
    • pending/disabled domains cannot be default;
    • the current default cannot be disabled or deleted until another active domain is made default;
    • source = env domains cannot be deleted from the UI (they would be re-seeded); they can be disabled, and detach to ui when removed from URLET_DOMAINS. The system domain can be neither disabled nor deleted;
    • a ui domain can be deleted only when it has no links at all, including soft-deleted links.
  • Every mutation is audited (domain.created, domain.updated, domain.deleted, domain.default_changed) and reloads the registry.

9. Security

  • Session cookies remain host-only; login and the application live on the canonical host only.
  • Unlock tokens and cookie names bind both hostname and slug, so a token issued for a.example.com/promo cannot unlock b.example.com/promo.
  • Click recording excludes every active hostname (plus the canonical host, localhost and 127.0.0.1) from referrer statistics.
  • The unlock rate-limit key includes the domain.
  • Redirect Location values always come from the stored target or configured canonical base URL; request Host is never used to build a redirect.
  • Captcha flows remain canonical-only in this version; a custom-domain white-label app would need per-domain site keys.
  • The existing CSRF same-origin check already accepts Origin/Referer that match the request Host, which covers the unlock form on extra domains.

10. Deployment

  • URLET_BASE_URL remains the canonical host and the only scheme source.
  • URLET_DOMAINS=go.example.com,links.example.com seeds extra domains. Seed rows are inserted as active, source = env, verified. They are never updated by the seed. When URLET_DOMAINS is set, removing a hostname from it detaches that domain to source = ui on the next boot (status, links and default are preserved); it is not deleted automatically.
  • Every added domain needs DNS pointing at the instance and a matching Caddy site block (automatic TLS). Caddy must be reloaded after adding a domain outside URLET_DOMAINS.
  • All domains must use the same http/https scheme as URLET_BASE_URL. An http-only extra domain cannot be represented while the canonical host is https.
  • The registry is in-process; this remains a single-instance SQLite deployment.

12. Out of scope (P2)

  • DNS TXT ownership verification and automatic activation.
  • Per-domain branding, themes or settings.
  • Per-user domain exceptions. Group-level defaults and allowlists are implemented by migration 0005_group_domains (user_groups.default_domain_id, restrict_domains, group_domains); only per-user overrides are out of scope.
  • Full white-label application on extra domains (login/dashboard/API).
  • Dynamic Caddy configuration from the admin UI.
  • Per-domain scheme and per-domain captcha keys.
