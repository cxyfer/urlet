2.1 Prebuilt image

Every v* tag publishes a multi-arch image (linux/amd64, linux/arm64) to GHCR. To run a published release instead of building locally:

  • URLET_IMAGE defaults to ghcr.io/cxyfer/urlet:latest; pin an exact version in production rather than tracking latest. When you do use latest, run docker compose -f docker-compose.yml -f docker-compose.image.yml pull before up -d to fetch a newer release.
  • The overlay removes the build section, so compose pulls the image and never falls back to a local Rust build.
  • The package defaults to private. Either authenticate (docker login ghcr.io with a token that has read:packages) or make the package public under Package settings → Change visibility.
  • The image runs as uid/gid 10001, exactly like a locally built one, so the /data volume permissions are unchanged.

3. Automatic HTTPS (Caddy)

  • Point the A/AAAA record for s.example.com at this host first; Caddy obtains and renews the certificate automatically.

5. Multi-domain deployments

Upgrading from 1.2 or older: back up the SQLite database first. The multi-domain migration (0003_multi_domain) rebuilds the urls table so the slug namespace becomes per domain; the migration is tested to preserve clicks, tags and daily stats, but a backup is the only rollback.

The canonical host keeps the application (/, /app, /api/v1). Extra domains are redirect-only: /{slug} and /{slug}/unlock work, / renders the theme-aware short landing page with the site tools, /app is redirected to the canonical host and /api returns 404. Each domain has its own slug namespace. The full design is in MULTI_DOMAIN.md.

  • Seed extra domains with URLET_DOMAINS=go.example.com,links.example.com, or add them from /app/admin/domains.
  • Domains added in the admin UI start as pending. Point DNS at this instance, add the hostname to the Caddy site label (or your reverse proxy), verify https://<domain>/health, then press Activate.
  • The canonical domain cannot be disabled or deleted. The current default domain must be replaced before it can be disabled or deleted. If URLET_BASE_URL changes, the previous canonical domain is demoted to ordinary admin management on the next boot (its links keep working) and the default moves to the new canonical domain when the old one held it.
  • All domains must use the same scheme as URLET_BASE_URL; do not mix http and https domains.
  • The reverse proxy must preserve the original Host header. X-Forwarded-Host is not trusted in this version.
  • URLET_DOMAINS is insert-only: disabling a seeded domain in the UI survives a restart. When the variable is set, removing a hostname from it detaches that domain to ordinary admin management on the next boot (status, links and default are preserved); it is not deleted automatically. Docker Compose always passes the variable, so an empty URLET_DOMAINS is treated as an explicit empty list.

6. Bot verification (CAPTCHA)

urlet can require a CAPTCHA on the three public forms that create state: the web registration form, the web sign-in form, and the web create-short-link form. The JSON API endpoints POST /api/v1/auth/register and POST /api/v1/auth/login are covered as well; they take the widget token in the optional captcha_token field. POST /api/v1/urls is covered too, but only for session-cookie calls (the link-creation switch); a call carrying Authorization: Bearer ur_... stays exempt, so automation keeps working. Verification is disabled by default.

Supported providers

ProviderValueNotes
DisablednoneDefault. No widget is rendered and nothing is verified
Cloudflare TurnstileturnstilePrivacy-friendly, free tier, usually invisible to the visitor
Google reCAPTCHA v2recaptchaThe "I'm not a robot" checkbox

Variables

All seven URLET_CAPTCHA_* variables are listed in the configuration reference. The shipped docker-compose.yml passes every one of them through, so setting them in .env is enough — no compose edit is needed.

Verification becomes active for a form only when all four conditions hold: the provider is not none, the site key is non-empty, the secret key is non-empty, and the matching ON_* switch (URLET_CAPTCHA_ON_REGISTER, URLET_CAPTCHA_ON_LOGIN or URLET_CAPTCHA_ON_CREATE) is true. Setting a provider without keys, or keys without a provider, silently leaves verification off.

Failure is closed: a missing, malformed, expired or already-used token — including a timeout or any non-2xx response from the provider — rejects the submission. On the web forms the visitor sees a validation error; POST /api/v1/auth/register, POST /api/v1/auth/login and a session-cookie POST /api/v1/urls return 400 with error.code = "captcha_failed" when the matching switch is enabled.

Token hostname (deployments with several hostnames)

Both providers report the hostname the token was solved on in the siteverify response, and urlet verifies it: the token must have been solved on this instance. The reported hostname must therefore equal the host of URLET_BASE_URL, or one of the extra hostnames listed in URLET_CAPTCHA_ALLOWED_HOSTNAMES. A response whose hostname is missing or empty is accepted — not every provider or widget configuration returns the field.

URLET_CAPTCHA_ALLOWED_HOSTNAMES takes a comma-separated list of bare hostnames: each item is trimmed and lowercased, empty items are dropped, and at most 10 items of 1–253 characters are kept. Entries must not contain whitespace, /, : or @. Leaving it empty means "only the host of URLET_BASE_URL", which is the right setting for the common single-domain deployment.

If your instance serves the forms on more than one hostname (for example a short-link domain and a separate application domain, or an extra alias), list every one of those hostnames here. Tokens solved on a hostname that is neither the URLET_BASE_URL host nor on the list are rejected, which shows up as "the visitor solves the CAPTCHA but still cannot register or sign in". On a mismatch urlet logs a WARN line containing the reported hostname and the list of accepted candidates, which is the fastest way to find the missing entry.

Getting the keys

Cloudflare Turnstile

  1. Sign in to the Cloudflare dashboard and open Turnstile.
  2. Choose Add widget, name it, and add the hostname(s) visitors will use to reach urlet (for example s.example.com; add localhost as well if you want to test locally).
  3. Pick a widget mode (Managed is a good default) and create the widget.
  4. Copy the Site Key and the Secret Key.

Google reCAPTCHA v2

  1. Open the reCAPTCHA admin console and register a new site.
  2. Select reCAPTCHA v2 → "I'm not a robot" Checkbox.
  3. Add the domain(s) of your instance.
  4. Copy the Site key and the Secret key.

remoteip behind a reverse proxy

Server-side verification sends the visitor's IP address as remoteip so the provider can score the request. urlet resolves that address exactly like the rate limiter does:

  • URLET_TRUST_PROXY=false (the default) — the address is the direct peer, which is the proxy itself when one sits in front of urlet. Every visitor then looks like the same client to the provider, and only the token's own signals are used for scoring.
  • URLET_TRUST_PROXY=true — X-Real-IP is preferred, falling back to the rightmost entry of X-Forwarded-For. The shipped deploy/Caddyfile sets header_up X-Real-IP {remote_host}, so Caddy passes the real visitor address.
  • When no address can be determined, remoteip is omitted; both provider APIs treat it as optional, so verification still works.

Only enable URLET_TRUST_PROXY when the proxy is guaranteed to overwrite X-Real-IP / X-Forwarded-For; otherwise a client can forge its address and also evade the rate limits.

10. Reverse proxy notes

  • Always set URLET_BASE_URL to the URL users actually see, otherwise short links point at the wrong domain.
  • Only enable URLET_TRUST_PROXY when the proxy is guaranteed to overwrite X-Forwarded-For / X-Real-IP; otherwise clients can forge their IP and bypass the rate limits. The application prefers X-Real-IP (set by the proxy itself) and otherwise takes the rightmost entry of X-Forwarded-For, so appending proxies are safe too. The shipped deploy/Caddyfile already sets header_up X-Real-IP {remote_host}.
  • Host, X-Forwarded-For and X-Forwarded-Proto must be forwarded; Caddy handles this automatically.
  • Invite links carry the code in ?invite=; reverse-proxy access logs that record query strings expose it. Restrict or redact those logs, or share the code instead.

11. Monitoring

  • Health check: GET /health (200 = healthy, 503 = database problem)
  • The container ships a HEALTHCHECK that runs urlet healthcheck (the image needs no curl)
  • Logs go to stdout; URLET_LOG_FORMAT=json pairs well with a collector such as Loki or CloudWatch
  • Every request carries an x-request-id response header, and the same id is written to the log
  • Admin → Overview in the admin UI shows the user count, short link count, total clicks and database size

SymptomCause and fix
Startup fails with a migration checksum mismatchA file in migrations/ that was already applied has been edited; restore it or add a new migration instead
Signed out immediately after signing inURLET_BASE_URL does not match the real URL, or URLET_SECURE_COOKIES=true while browsing over HTTP
Short links point at http://localhost:8080URLET_BASE_URL is not set
/health returns 503 after the container startsVolume permission problem: /data must be writable (the container runs as uid 10001)
Rate limits hit legitimate users (many users behind NAT)Loosen the limits or switch those clients to API tokens; limits are counted per IP
Login returns 429 even with the correct passwordThe account is temporarily locked (30 failures within 15 minutes). Wait for the window to slide past, or run sqlite3 /data/urlet.db "DELETE FROM login_attempts" to clear it immediately
The CAPTCHA widget never appearsAll four conditions must hold: a provider other than none, both keys, and the matching ON_* switch set to true
Every submission fails with captcha_failedThe secret key does not belong to the configured provider, the widget's hostname list does not include the domain users visit, or an API client forgot to send the widget token as captcha_token
The visitor solves the CAPTCHA but registration or sign-in still failsThe token was solved on a hostname that urlet does not accept: add it to URLET_CAPTCHA_ALLOWED_HOSTNAMES (the WARN log line names the reported hostname and the accepted candidates)
Want token access after forgetting the admin passwordResetting a password revokes every API token for that account (by design); create a new token afterwards
Forgot the admin passwordThe startup bootstrap runs only when both URLET_ADMIN_EMAIL and URLET_ADMIN_PASSWORD are non-empty, and for an account that already exists it merely promotes it to administrator — it does not change the password (the password is used only when the account does not exist yet). To recover, point URLET_ADMIN_EMAIL at another account you can still sign in to (any non-empty URLET_ADMIN_PASSWORD makes the bootstrap run), restart, and use that account; or overwrite the password hash directly with sqlite3
A short link expired and you want it backOpen /app/urls/{id} and extend it, or clear the expiry under "Edit settings"; the data was never deleted
Want to reuse a slug after deleting a short linkDeliberately not allowed (so old links cannot be hijacked); pick a new slug

13. Security checklist

  • URLET_BASE_URL uses https://
  • URLET_ADMIN_PASSWORD is a strong password, changed at /app/account after the first sign-in
  • URLET_SECRET is set (at least 32 random characters), or the auto-generated secret.key (0600) is backed up
  • Only 80/443 are reachable from the internet. The base compose file publishes ${URLET_PORT:-8080}:8080 on every interface; the TLS overlay removes that publish, so use the overlay or firewall the port
  • URLET_TRUST_PROXY matches the actual proxy behavior
  • The registration mode is invite or closed (unless you really want open registration)
  • click_retention_days and a backup schedule are planned
  • A regular update routine exists (rebuild locally or pull a new URLET_IMAGE tag), with a backup before each upgrade
  • Bot verification is enabled on registration and sign-in if the instance is reachable by the public internet
