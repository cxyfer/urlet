# 安全政策

[English](../../SECURITY.md) | **繁體中文**

urlet 是自架服務：每個執行個體都由各自的營運者維護，漏洞在營運者升級前都會持續可被利用。
請以私密管道回報安全問題，保留發布修正版本的時間，之後再公開細節。

  或不予修正。
- 營運者需自行負責其執行個體：升級、保護主機與反向代理、備份資料，以及判斷 urlet 是否符合需求。
  若要用於高風險或有法規遵循要求的情境，請先自行審查。

## 支援的版本

安全修正會合併進 `master`，並以最新正式次版本的修補版本發布。較舊的次版本與 `-rc.N` 預發布
版本不會回移修正；請升級到最新版本以取得修正。

| 版本 | 是否支援 |
| --- | --- |
| 最新正式次版本（目前為 `1.4.x`） | 是 |
| 較舊的次版本 | 否 |
| 預發布版本（`-rc.N`） | 否 |

## 回報漏洞

**請勿為安全問題開公開的 issue、pull request 或 discussion。**

請透過 GitHub 的私密漏洞回報功能提交：
[**Report a vulnerability**](https://github.com/cxyfer/urlet/security/advisories/new)，也可以從
repo 的 *Security* 分頁進入。回報內容只有維護者看得到。

有幫助的回報會包含：

- urlet 的版本或 commit，以及部署方式（Docker 映像、執行檔、前方的反向代理、相關的 `URLET_*`
  設定，例如 `URLET_TRUST_PROXY`）；
- 受影響的端點、頁面或元件；
- 重現步驟，最好是 `curl` 指令或簡短的腳本；
- 攻擊者能得到什麼，以及需要哪種身分（匿名訪客、註冊使用者、群組成員、管理員）。

請在自己架設的執行個體上測試。不要測試不屬於你的執行個體，也不要存取或修改他人的資料。

## 回報之後

以下是目標而非保證（見[免責聲明](#免責聲明)）：

1. 7 天內回覆確認收到回報。
2. 確認或排除問題，並與你商定嚴重度；進度會在 advisory 討論串中更新。
3. 在 advisory 的私密 fork 中開發修正，然後發布修補版本。
4. 新版本可取得後公開 GitHub Security Advisory 並附上升級說明；除非你希望匿名，否則會列名致謝。

在 advisory 公開前，請勿公開細節。

## 範圍

範圍內是本 repo 的程式碼：`urlet` 執行檔及其內嵌的資源與模板、由 [`Dockerfile`](../../Dockerfile)
建置的容器映像，以及 [`deploy/`](../../deploy) 下的範例部署檔與 `docker-compose*.yml`。

以下不在範圍內，或視為加固項目而非漏洞：

- **需要管理員權限的操作。** 管理員是受信任的角色：他們管理使用者、網域、設定與自訂主題 CSS。
  非管理員取得這些權限的方法則在範圍內。
- **需要主機存取權的操作**，例如存取 SQLite 資料庫、資料目錄或 secret 金鑰檔。
- **設定錯誤的部署**，例如在會轉送客戶端自帶 `X-Real-IP` 或 `X-Forwarded-For` header 的代理後方
  啟用 `URLET_TRUST_PROXY`。部署文件不清楚或有誤，歡迎以一般 issue 回報。
- **流量型阻斷服務**，以及只受攻擊者頻寬限制的暴力破解。繞過既有限制（例如登入鎖定）的方法則在
  範圍內。
- **指向惡意網站的短網址。** 轉址到任意網址是短網址服務的本質，濫用處理由各營運者負責。繞過執行
  個體強制的限制（例如訪客目標白名單）則在範圍內。
- **相依套件的漏洞**，若沒有展示對 urlet 的實際影響。這類問題請回報給上游。
