2.1 使用預先建置的映像

每次推送 v* 標籤都會發布多架構映像（linux/amd64、linux/arm64）到 GHCR。若不想在本機 建置，可直接執行已發布的版本：

  • URLET_IMAGE 預設為 ghcr.io/cxyfer/urlet:latest；正式環境請固定精確版本，不要長期 追蹤 latest。若使用 latest，請在 up -d 前先執行 docker compose -f docker-compose.yml -f docker-compose.image.yml pull，才會取得較新的版本。
  • overlay 會移除 build 設定，因此 compose 只會拉取映像，不會退回本機 Rust 建置。
  • 套件預設為私有。請先登入（docker login ghcr.io，權杖需具備 read:packages），或在 Package settings → Change visibility 將套件改為公開。
  • 映像以 uid/gid 10001 執行，與本機建置的映像相同，因此 /data volume 的權限設定不變。

5. 多網域部署

從 1.2 或更舊版本升級： 請先備份 SQLite 資料庫。多網域 migration （0003_multi_domain）會重建 urls 表，把 slug 命名空間改為以網域為單位；migration 已測試 會保留 clicks、tags 與每日統計，但備份是唯一的回滾方式。

Canonical host 保留完整應用（/、/app、/api/v1）。額外網域只做轉址：/{slug} 與 /{slug}/unlock 可用，/ 顯示會套用主題的短網址導覽頁並帶站台工具，/app 導回 canonical， /api 回 404。每個網域有自己的 slug 命名空間。完整設計見 MULTI_DOMAIN.md。

  • 用 URLET_DOMAINS=go.example.com,links.example.com 預先加入，或從 /app/admin/domains 新增。
  • 後台新增的網域是 pending。先把 DNS 指向此實例、把 hostname 加進 Caddy site label（或你的 反向代理），確認 https://<domain>/health 可用後，再按「啟用」。
  • Canonical 網域不可停用或刪除；目前的預設網域必須先換掉，才能停用或刪除。若 URLET_BASE_URL 改變，下次啟動會把舊 canonical 網域降級為一般管理網域（既有連結繼續可用），並在舊網域原本是 預設時把預設轉移到新 canonical 網域。
  • 所有網域必須和 URLET_BASE_URL 使用相同 scheme，不要混用 http 與 https。
  • 反向代理必須保留原始的 Host header；本版本不信任 X-Forwarded-Host。
  • URLET_DOMAINS 只補缺少：在後台停用 seed 網域後，重啟不會被改回 active。在有設定 URLET_DOMAINS 的前提下，把 hostname 從環境變數移除後，下次啟動會 detach 成一般管理網域 （保留狀態、連結與預設），不會自動刪除。Docker Compose 一律會傳入此變數，因此空的 URLET_DOMAINS 會被視為明確的空清單。

6. 防機器人驗證（CAPTCHA）

urlet 可以要求三個會產生資料的公開表單通過防機器人驗證：網頁註冊表單、網頁登入表單與 網頁建立短網址表單。JSON API 的 POST /api/v1/auth/register 與 POST /api/v1/auth/login 也涵蓋在內，兩者以選填欄位 captcha_token 接收驗證元件的權杖。POST /api/v1/urls 同樣在 範圍內，但僅限 Session Cookie 呼叫（受建立短網址開關約束）；帶 Authorization: Bearer ur_... 的呼叫維持豁免，自動化流程不受影響。預設關閉。

支援的供應商

供應商值說明
關閉none預設。不渲染驗證元件，也不做任何驗證
Cloudflare Turnstileturnstile注重隱私、有免費額度，通常使用者無感
Google reCAPTCHA v2recaptcha「我不是機器人」核取方塊

環境變數

七個 URLET_CAPTCHA_* 變數都列在設定參考。出貨的 docker-compose.yml 會把 它們全部轉傳到容器，因此只要寫進 .env 即可，不需要改 compose。

四個條件全部成立時，該表單才會啟用驗證：provider 不是 none、site key 非空、 secret key 非空，以及對應的 ON_* 開關（URLET_CAPTCHA_ON_REGISTER、 URLET_CAPTCHA_ON_LOGIN 或 URLET_CAPTCHA_ON_CREATE）為 true。 只設定 provider 而沒有金鑰，或只有金鑰而沒有 provider，都會讓驗證維持關閉。

驗證失敗一律拒絕（fail closed）：token 缺少、格式錯誤、逾期或已使用過， 以及逾時或供應商回應非 2xx，都會拒絕該次提交。網頁表單會顯示驗證錯誤訊息； 對應開關啟用時，POST /api/v1/auth/register、POST /api/v1/auth/login，以及使用 Session Cookie 的 POST /api/v1/urls，都會回 400 且 error.code = "captcha_failed"。

Token 的主機名稱（多主機名稱部署）

兩家供應商都會在 siteverify 回應中回報 token 是在哪個主機名稱解出的，urlet 會加以驗證： token 必須是在本站解出的。因此回報的 hostname 必須等於 URLET_BASE_URL 的主機名稱， 或是 URLET_CAPTCHA_ALLOWED_HOSTNAMES 中列出的其中一個。回應未帶 hostname 或該欄位為空字串 時會予以接受 —— 並非每個供應商或元件設定都會回傳這個欄位。

URLET_CAPTCHA_ALLOWED_HOSTNAMES 接受以逗號分隔的裸主機名稱清單：每一項會 trim、轉小寫、 丟棄空項，最多保留 10 項，每項 1–253 字元；內容不得含空白、/、: 或 @。 留空代表「只接受 URLET_BASE_URL 的主機名稱」，這也是常見單一網域部署的正確設定。

若你的實例以多個主機名稱提供表單（例如短網址網域與應用網域不同，或另有別名）， 就必須把那些主機名稱全部列在這裡。若 token 解出的主機名稱既不是 URLET_BASE_URL 的主機 名稱、也不在清單中，就會被拒絕，症狀是「使用者填完驗證碼仍無法註冊或登入」。 發生不符時 urlet 會記一筆 WARN，內容包含回報的 hostname 與目前接受的候選清單， 是找出漏填項目最快的方法。

反向代理後面的 remoteip

伺服器端驗證會把訪客 IP 以 remoteip 傳給供應商，讓供應商做風險評分。 urlet 解析這個位址的方式與速率限制完全相同：

  • URLET_TRUST_PROXY=false（預設）——採用直接連線的對方位址；前面有代理時， 那就是代理自己的位址。此時所有訪客在供應商眼中都是同一個用戶端， 評分只依賴 token 本身的訊號。
  • URLET_TRUST_PROXY=true——優先採用 X-Real-IP，其次取 X-Forwarded-For 最右側的位址。 隨附的 deploy/Caddyfile 已設定 header_up X-Real-IP {remote_host}， 因此 Caddy 會傳遞真實的訪客位址。
  • 無法判斷位址時會省略 remoteip；兩家供應商的 API 都把它視為選填，驗證仍可正常運作。

只有在代理保證覆寫 X-Real-IP / X-Forwarded-For 時才開啟 URLET_TRUST_PROXY， 否則客戶端可以偽造 IP，同時繞過速率限制。

10. 反向代理注意事項

  • 一定要設定 URLET_BASE_URL 為使用者實際看到的網址，否則短網址會指向錯誤的網域。
  • 只有在代理保證覆寫 X-Forwarded-For / X-Real-IP 時才開啟 URLET_TRUST_PROXY， 否則客戶端可以偽造 IP 繞過速率限制。程式優先採用 X-Real-IP（代理自行設定）， 其次取 X-Forwarded-For 最右側的位址，因此附加式代理也安全； 隨附的 deploy/Caddyfile 已設定 header_up X-Real-IP {remote_host}。
  • 需要傳遞 Host、X-Forwarded-For、X-Forwarded-Proto；Caddy 會自動處理。
  • 邀請連結會在 ?invite= 攜帶邀請碼；若反向代理的存取日誌記錄 query string，就會留下邀請碼。 請限制或遮蔽該日誌，或改為只分享邀請碼。

11. 監控

  • 健康檢查：GET /health（200 = 正常，503 = 資料庫異常）
  • 容器 HEALTHCHECK 已內建，使用 urlet healthcheck（映像檔不需要 curl）
  • 日誌輸出到 stdout；URLET_LOG_FORMAT=json 可搭配 Loki/CloudWatch 之類的收集器
  • 每個請求都有 x-request-id 回應標頭，並以相同 id 寫入日誌
  • 管理後台 Admin → Overview 可看使用者數、短網址數、點擊總量、資料庫大小

13. 安全檢查清單

  • URLET_BASE_URL 使用 https://
  • URLET_ADMIN_PASSWORD 為強密碼，且登入後於 /app/account 更換
  • 設定 URLET_SECRET（至少 32 個隨機字元）或確保自動產生的 secret.key（0600）已備份
  • 對外只開放 80/443。基礎 compose 檔會在所有介面發布 ${URLET_PORT:-8080}:8080；TLS overlay 會移除這個發布，因此請使用 overlay 或以防火牆封鎖該連接埠
  • 確認 URLET_TRUST_PROXY 的設定與代理行為一致
  • 註冊模式設為 invite 或 closed（除非真的要開放註冊）
  • 已規劃 click_retention_days 與備份排程
  • 有固定的更新流程（本機重建或拉取新的 URLET_IMAGE 標籤），且每次升級前先備份
  • 若實例可從公網連線，已為註冊與登入流程啟用防機器人驗證
